Improved Garrisons v1.1.7 - BannerlordCoop dedicated server
=============================================================

This package is one custom Bannerlord module.

The BannerlordCoop appliance launches a fixed module set (Coop,
DedicatedServer.Windows, Native, SandBox, SandBoxCore) and accepts only one
primary DedicatedServer.Windows submodule. A module folder dropped next to
those five is never loaded, no matter what a hosting setup's own bookkeeping
files claim is active; nothing in the engine reads those files to decide what
to load.

ServerInstall/DedicatedServer.Windows.SubModule.xml is the only mechanism that
makes the appliance actually run Improved Garrisons code. It adds a second
<SubModule> entry to DedicatedServer.Windows's manifest, alongside the stock
one, declaring the Improved Garrisons Coop bootstrap
(ImprovedGarrisons.CoopBootstrap.dll / ImprovedGarrisons.CoopBootstrap.
IntegrationSubModule). The bootstrap loads the stock DedicatedServer.Windows
submodule first, forwards its real lifecycle overrides, waits for
BannerlordCoop's native MobileParty registry and constructor prefix to be
ready, and only then activates Improved Garrisons server simulation.

Prerequisites
-------------

  - A working BannerlordCoop dedicated server, already installed and able to
    boot on its own before you add this module. This release targets game
    v1.4.8. Automated runtime contracts were checked against BannerlordCoop
    v0.1.5 and its dedicated-server build 2026-09-06 (paired Coop commit
    4ad976c8); an in-game smoke test is still required.
  - The complete dedicated-server package paired with that Coop build.
    The appliance verifies the SHA-256 hashes of its Coop assemblies at
    startup and before listening. Replacing only engine/Modules/Coop with a
    different client build can stop startup with exit code 4. Update the
    appliance as a matched package and use the matching Coop build on clients.
    IG's manifest patch belongs in DedicatedServer.Windows; leave the
    appliance's engine/Modules/Coop files unchanged.
  - File access to that dedicated server's own install root -- the folder
    that directly contains its "engine/" subfolder (this is BannerlordCoop's
    own dedicated-server layout, the same regardless of whether you deployed
    it through a hosting panel, plain Docker, or by hand). Every path below
    is written relative to that root.
  - The ability to create a file link there, not just copy files: on a
    Linux/Wine-hosted server that is `ln -s`; on a native Windows host it is
    `mklink`. Steps 3-4 explain why a plain copy silently breaks updates.
  - Some hosting setups (for example an automated panel script) already do
    steps 3-4 for you on every boot. Check for that first -- rerunning them
    by hand is harmless either way -- and use the Verification section below
    to confirm the result regardless of how it was applied.

Install
-------

1. Stop the dedicated server and back up its persistent data directory,
   including the campaign save, paired session JSON, IG settings and backups.
2. Copy this complete folder to:

     engine/Modules/ImprovedGarrisons

3. ImprovedGarrisons.CoopBootstrap.dll must be reachable from both
   engine/Modules/DedicatedServer.Windows/bin/Win64_Shipping_Client/ and
   .../Win64_Shipping_Server/ -- as a link to the DLL inside this
   ImprovedGarrisons folder, never a separate copy (a copy will not receive
   future updates and will silently drift from the real module). If nothing
   already creates these links for you, create them yourself, for example
   on a Linux/Wine host:

     ln -sf ../../../ImprovedGarrisons/bin/Win64_Shipping_Client/ImprovedGarrisons.CoopBootstrap.dll \
       engine/Modules/DedicatedServer.Windows/bin/Win64_Shipping_Client/ImprovedGarrisons.CoopBootstrap.dll
     ln -sf ../../../ImprovedGarrisons/bin/Win64_Shipping_Server/ImprovedGarrisons.CoopBootstrap.dll \
       engine/Modules/DedicatedServer.Windows/bin/Win64_Shipping_Server/ImprovedGarrisons.CoopBootstrap.dll

   These link targets are relative to each link's directory. Run the commands
   from the appliance install root. On Windows, use `mklink` to the same effect.
4. Back up engine/Modules/DedicatedServer.Windows/SubModule.xml, then replace
   it with the content of:

     ImprovedGarrisons/ServerInstall/DedicatedServer.Windows.SubModule.xml

5. Start the server.

Verification (do this, not just reading a console banner)
--------------------------------------------------------------

A hosting setup's own startup banner (for example one that lists "active
modded server modules") only proves that setup's own bookkeeping was
updated -- it does NOT prove the engine loaded the module. Confirm the real
thing instead:

  - engine/Modules/ImprovedGarrisons/ModuleData/CoopRuntime.status must exist
    after the server finishes booting. Its absence means step 4 above was not
    applied (or was reverted by an update -- see "Durability" below).
  - The bootstrap logs "[ImprovedGarrisons] Coop bootstrap loaded; waiting for
    BannerlordCoop networking." to the server's own console/stdout on boot.
  - CoopRuntime.status should progress to native-mobile-party-registry-ready
    and then transport-connected:server as a client joins.

Durability -- reapply after updates
--------------------------------------

Step 4 patches a file owned by the BannerlordCoop appliance
(DedicatedServer.Windows), not by this module. An appliance/Coop update that
re-extracts that module's own files will silently discard the patch, and the
server will boot with Improved Garrisons never running again -- with no error,
just total silence from every Improved Garrisons action. There is currently no
way to make this self-healing from inside this module or this repository (it
would require editing the appliance's own startup script, which is outside
this module's control and resets on update the same way). Re-run steps 3-4
after every BannerlordCoop/appliance update: replacing the appliance can
remove the bootstrap links as well as the manifest patch. Check the
Verification section above afterward.

Coop v0.1.5 configuration and saves
----------------------------------

Use the data directory printed in the appliance's boot banner. By default:

  Documents/Mount and Blade II Bannerlord/CoopData/DedicatedServer

The launcher accepts --data-dir <path> to select another directory. Keep it
outside the replaceable appliance install folder and retain the same path
when updating. With a container or Wine host, persist the actual directory
used by that process, not a different host user's Documents folder.

Server settings live in <data dir>/server-config.json: saveName,
autosaveMinutes (0 disables autosaving), password, logFile, and steam.
Edit the file and restart the server. If saveName does not identify an
existing save, Coop creates a new world from default_new_game.sav, so retain
the previous saveName when upgrading an existing campaign.

Campaign saves and paired session JSON live in <data dir>/Game Saves.
Coop retains two backup generations, .backup1 and .backup2, with their paired
session JSON. Back up and restore each save together with its matching JSON.

Coop gameplay settings are separate: mod-config.json defaults to the shared
CoopData directory one level above DedicatedServer. COOP_DATA_DIR overrides
that shared config directory; BANNERLORD_USER_DIR identifies the dedicated
save directory used by IG. If COOP_DATA_DIR is unset, Coop's config resolver
can fall back to BANNERLORD_USER_DIR, putting mod-config.json beside the server
data instead. Check the startup paths when a hosting script sets these values.
Refer to the matched appliance's release-info.txt for its startup settings,
networking, and exact paired build.

Persistent Coop data
--------------------

On the dedicated server, Improved Garrisons stores its Coop settlement
settings and generated-party identity manifest under:

  <BannerlordCoop data dir>/ImprovedGarrisons

The server obtains the exact data directory from BannerlordCoop's
BANNERLORD_USER_DIR environment variable, so a custom --data-dir is honored.
This location sits beside the Coop Game Saves folder and survives replacement
of the DedicatedServer install tree. On the first fixed-version boot, the four
known IG state/backup files are copied from the legacy
DedicatedServer/server-data/improved-garrisons folder when no persistent copy
already exists. No Coop save or player-registration JSON file is migrated or
modified.

Settings restore after BannerlordCoop finishes loading the campaign and saved
players, before IG accepts settings changes or sends the initial settings sync.
Saved players' clans remain recognized even while those players are offline.
Coop ownership refreshes retain settings; a transfer to another clan clears the
previous owner's settings. Ordinary mod updates do not reset these files.

Changed settings are written atomically and failed writes are retried. The
settlement-settings.txt.bak file retains the previous settings change; routine
activity updates do not replace that backup. If restoration fails, IG logs the
failure and leaves the file intact instead of overwriting it with defaults.
Keep the data directory and its backups when updating either module. A file
already deleted by an earlier install/update cannot be reconstructed by IG.

Client install
--------------

Copy the same complete ImprovedGarrisons folder under the client's Bannerlord
Modules directory. Client and server DLLs in this package are byte-identical.
Replace both sides together whenever updating: BannerlordCoop excludes
Official modules from its version comparison, so it cannot detect an older
Improved Garrisons client by itself.

Improved Garrisons uses BannerlordCoop's own dedicated-server connection state
as the only campaign-readiness authority -- there is no separate Improved
Garrisons handshake, socket, listener, or server process. The dedicated server
accepts intents and answers configuration/state/manifest/health requests only
after Coop's own IConnectionCollection reports that peer has completed
campaign synchronization. All Improved Garrisons traffic travels through
Coop's INetwork and IMessageBroker.
