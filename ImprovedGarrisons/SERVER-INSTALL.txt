Improved Garrisons v1.0.1 - BannerlordCoop dedicated server
===========================================================

This package is one custom Bannerlord module. Do not install CoopModPatch or
the abandoned reflection bridge.

This BannerlordCoop appliance launches a fixed module set, ignores dropped-in
module folders, and accepts only one primary DedicatedServer.Windows submodule.
ServerInstall/DedicatedServer.Windows.SubModule.xml therefore registers the
dependency-free Improved Garrisons bootstrap as that primary entry. The
bootstrap instantiates the genuine DedicatedServer.Windows submodule and
forwards only its four real overrides before running Improved Garrisons.

Clean install
-------------

1. Stop the dedicated server and back up the current campaign save.
2. Restore the stock DedicatedServer.Windows module from the server appliance.
3. Remove any ImprovedGarrisons.CoopServerBridge.dll left in either
   DedicatedServer.Windows bin directory.
4. Remove the separate CoopModPatch module unless another installed mod
   explicitly requires it. Improved Garrisons does not use it.
5. Copy this complete folder to:

     engine/Modules/ImprovedGarrisons

6. Create this directory if the appliance does not contain it:

     engine/Modules/DedicatedServer.Windows/bin/Win64_Shipping_Client

7. Create links named ImprovedGarrisons.CoopBootstrap.dll in both
   DedicatedServer.Windows bin directories. Each link must target the matching
   DLL inside ImprovedGarrisons. Do not copy a separate build of the code.
8. Back up DedicatedServer.Windows/SubModule.xml, then replace it with:

     ImprovedGarrisons/ServerInstall/DedicatedServer.Windows.SubModule.xml

   The bootstrap loads the stock DedicatedServer.Windows.dll, invokes its
   OnSubModuleLoad first, verifies BannerlordCoop's native MobileParty registry
   and constructor prefix, and only then activates Improved Garrisons server
   simulation. Deferred campaign lifecycle calls are replayed after readiness.
   It forwards no invented DedicatedServer lifecycle methods.
9. Make ImprovedGarrisons the only custom entry in modded-server-modules.txt.
10. Start the server normally. The Pterodactyl console must show only:

     [egg] active modded server modules:
     ImprovedGarrisons

   The module writes its last activation stage to
   ModuleData/CoopRuntime.status. During bring-up a healthy server reaches:

     native-mobile-party-registry-ready

   and then, after the IG service binds to Coop networking:

     transport-connected:server

   A native-mobile-party-registry-unavailable,
   native-mobile-party-constructor-prefix-unavailable, or
   native-mobile-party-postcondition-failed status is fail-closed: IG party
   simulation remains blocked and activation retries. Preserve that status and
   the matching server log before changing the installation.

The module never edits the server startup command, module list, policy file,
or DedicatedServer.Windows files at runtime.

Client install
--------------

Copy the same complete ImprovedGarrisons folder under the client's Bannerlord
Modules directory. Client and server DLLs in this package are byte-identical.
Replace both sides together whenever updating: BannerlordCoop excludes Official
modules from its version comparison, so it cannot detect an older Improved
Garrisons client by itself.

Starting with v1.0.1, the Improved Garrisons server sends no custom state or
health packets until that client completes the Improved Garrisons compatibility
hello. This keeps an absent or older client from disrupting Coop's connection
validation. A matching pair logs "compatible Improved Garrisons peer
registered" on the server and "client/server compatibility verified" on the
client before configuration synchronization begins.

Acceptance check
----------------

After joining, confirm ordinary lords, caravans, and villagers continue moving
before creating a test guard, recruiter, transfer, and village-recruit party.
For each interactive action, confirm the server logs one received/completed
intent and Coop logs one native MobileParty lifetime creation. There is no
Improved Garrisons party-creation acknowledgement or replacement party payload;
the created party appearing through Coop replication is the completion signal.
